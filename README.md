## About

I'm a **Senior C++ Systems Engineer with 8.5+ years of experience** building, debugging, and optimizing software across **Web Content Management, FinTech, Telecom, and Embedded Systems**.

My engineering focus is on systems where **correctness, concurrency, throughput, memory efficiency, reliability, and maintainability** matter.

- **Modern C++:** C++11/14/17, STL, RAII, smart pointers, templates, move semantics, OOD and design patterns
- **Linux Systems:** Linux/Unix, POSIX APIs, processes, IPC, file systems, FUSE and daemon applications
- **Concurrency:** multithreading, synchronization, mutexes, condition variables, thread safety and concurrent processing
- **Performance:** profiling, memory optimization, CPU analysis, contention, throughput and latency-sensitive components
- **Networking:** TCP/IP, sockets, client/server architecture and TLS/SSL
- **Storage:** B+ trees, key-value stores, persistence, transactions and write-ahead logging
- **Reliability:** GDB, Valgrind, core dumps, crash analysis, race/deadlock investigation and root-cause analysis

> I prefer building systems that are understandable, measurable, testable and reliable — not just systems that compile.

### 03 · Distributed In-Memory Data Storage & Loader

<a href="https://github.com/Krish1994-coder/Distributed-InMemory-Data-Storage-Loader">
  <img src="https://img.shields.io/badge/PRIVATE%20REPOSITORY-6F42C1?style=for-the-badge&logo=github&logoColor=white"/>
</a>

A **C++17 distributed in-memory data storage and loading system** designed around deterministic partitioning, local and remote record routing, batched transport, duplicate-key resolution and end-to-end verification.

The implementation models a **1–5 node cluster within a single process**, with per-node loader and receiver threads and a mock socket-style transport layer.

**Engineering areas**

`C++17` `Distributed Systems` `Data Partitioning` `Concurrency` `Batching` `Mock Networking` `In-Memory Storage` `Duplicate Resolution` `Verification`
